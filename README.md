# rag-tender-sql

Две независимые половины одной задачи: сервис поиска по базе знаний на FastAPI и схема
PostgreSQL для тендерной площадки с аналитическими запросами. Первая показывает работу с
эмбеддингами и генерацией по цитатам, вторая — модель данных и SQL, в котором целостность и
производительность живут в самой базе.

Обе части запускаются **без ключей, без сети и без внешних сервисов**: RAG-сервис поднимается
одной командой, схема разворачивается файлами `schema.sql` → `seed.sql`.

## Часть 1. RAG-сервис

FastAPI-сервис: принимает документ, режет его на чанки с перекрытием, строит векторы, ищет
по ним и отвечает на вопрос **со списком процитированных фрагментов**.

```bash
cd task3_rag
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest tests -q          # 6 passed, без ключей и сети
.venv/bin/uvicorn app.main:app --reload
```

```bash
curl -F 'file=@sample/regulation.txt' localhost:8000/documents
curl -s localhost:8000/ask -H 'Content-Type: application/json' \
     -d '{"question":"Сколько дней отпуска и за сколько подавать заявку?"}'
```

### Решения, которые стоит объяснить

**Сервис поднимается без ключей провайдеров.** Эмбеддинги: OpenAI, если есть
`OPENAI_API_KEY`, иначе локальный хеширующий векторизатор (словные + символьные 3-граммы,
L2-нормировка). Генерация: Anthropic → OpenAI → Ollama → extractive.

**Extractive — не заглушка ради зелёного теста.** Он возвращает найденные фрагменты без
перефразирования, поэтому ответ не может быть выдуман, а проверяющий запускает сервис на
чистой машине одной командой. Когда доступен провайдер, тот же контракт наполняется
сгенерированным текстом — с тем же списком цитат.

**Символьные n-граммы выбраны ради русского языка.** Словоизменение ломает точное
совпадение токенов, а n-граммы переживают его: «штрафы» находят «штрафа».

**FAISS не обязателен.** `VectorStore` использует `IndexFlatIP`, если `faiss` установлен, иначе
точный перебор на numpy за тем же интерфейсом. На объёме регламента (сотни чанков) разницы
нет; она появляется на сотнях тысяч векторов, и тогда меняется только реализация класса.

Ответ API содержит текст, использованный бэкенд генерации, и цитаты со скорами — видно,
откуда взят каждый фрагмент.

## Часть 2. Схема «Тендерная площадка»

`schema.sql` (DDL), `seed.sql` (данные), `queries.sql` (два аналитических запроса).

```bash
createdb tender_demo
psql -d tender_demo -f task4_db/schema.sql
psql -d tender_demo -f task4_db/seed.sql
psql -d tender_demo -f task4_db/queries.sql
```

### Модель

`companies` — одна таблица и для заказчиков, и для участников: в одном тендере компания
заказчик, в другом — участник, и разделение на две таблицы разъезжается на первом же таком
случае. `contractors` — роль исполнителя по конкретному договору, а не отдельный справочник
компаний.

### Целостность в базе, а не в приложении

| Ограничение | Что защищает |
|---|---|
| `bids_single_winner_per_lot` (частичный уникальный индекс) | У лота ровно один победитель |
| `bids_one_active_per_company` | Одна действующая ставка компании на лот; отозванная не мешает подать новую |
| `companies_inn_digits` | ИНН из 10 или 12 цифр |
| `numeric(16,2)` рядом с валютой | Деньги не превращаются в float |

Индексы подобраны под реальные запросы: диапазонные условия по времени (`signed_at`,
`published_at`), частичный индекс по открытым тендерам, поиск по ОКПД2.

### Аналитические запросы

1. **Топ-3 компании по сумме выигранных тендеров за предыдущий календарный месяц.**
   «Выигранный» считается по подписанному договору, а не по флагу `is_winner`: между
   объявлением победителя и договором лот может уйти второму участнику.
2. **Конкуренция и падение цены по лотам за квартал** — сколько участников торговалось, на
   сколько процентов победитель опустил НМЦ, с рангом заказчика по среднему падению
   (оконная функция вместо второго `GROUP BY`).

В обоих запросах условия остаются диапазонными по времени, поэтому индексы продолжают
работать; в комментариях указано, как сдвинуть окно на завершённый период.

## Ограничения

- Extractive-режим не перефразирует: это осознанный компромисс ради запуска без ключей.
- Хеширующие эмбеддинги слабее модельных на сложных вопросах; при наличии ключа
  подставляются провайдерские.
- FAISS-путь на объёме демо не проверялся (он не нужен на сотнях чанков).
- Часть 2 — схема и запросы, а не работающий сервис: приложение к ней не входит в репозиторий.
