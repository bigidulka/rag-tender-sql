## Задание 3 — RAG-сервис

FastAPI, чанкинг с перекрытием, эмбеддинги, векторный поиск, ответ по
процитированному контексту. Два решения, которые стоит объяснить отдельно:

**Сервис поднимается без ключей провайдеров.** Эмбеддинги: OpenAI, если есть
`OPENAI_API_KEY`, иначе локальный хеширующий векторизатор (словные + символьные
3-граммы, L2-нормировка). Генерация: Anthropic → OpenAI → Ollama → extractive.
Extractive — не заглушка ради зелёного теста: он возвращает найденные фрагменты
без перефразирования, поэтому ответ никогда не выдуман, а проверяющий запускает
сервис на чистой машине одной командой. Символьные n-граммы взяты ради русского
языка: они переживают словоизменение, и «штрафы» находят «штрафа».

**FAISS не обязателен.** `VectorStore` использует `IndexFlatIP`, если faiss
установлен, иначе точный перебор на numpy за тем же интерфейсом. На объёме
регламента (сотни чанков) разницы во времени нет, она начинается на сотнях тысяч
векторов — и тогда меняется только реализация класса.

## Задание 4 — схема «Тендерная площадка»

`companies` — одна таблица и для заказчиков, и для участников: в одном тендере
компания заказчик, в другом участник, разделение на две таблицы разъезжается на
первом же таком случае. `contractors` — роль исполнителя по конкретному
договору, а не отдельный справочник компаний.

Целостность вынесена в БД, а не оставлена приложению:

* `bids_single_winner_per_lot` — частичный уникальный индекс: победитель у лота
  ровно один;
* `bids_one_active_per_company` — одна действующая ставка компании на лот,
  отозванные не мешают подать новую;
* `companies_inn_digits` — ИНН из 10 или 12 цифр;
* деньги — `numeric(16,2)`, валюта хранится рядом с суммой.

Индексы поставлены под конкретные запросы мониторинга (свежие тендеры, открытые
на приём заявок, история ставок компании, договоры за период), а не на каждый
столбец.

Проверено на PostgreSQL 17: схема разворачивается, все три ограничения выше
реально отбивают некорректные вставки, оба запроса возвращают непустой результат
на `seed.sql`.

```bash
docker run --rm -d --name tender-db -e POSTGRES_PASSWORD=x -e POSTGRES_DB=tender postgres:17-alpine
docker exec -i tender-db psql -U postgres -d tender -v ON_ERROR_STOP=1 < task4_db/schema.sql
docker exec -i tender-db psql -U postgres -d tender -v ON_ERROR_STOP=1 < task4_db/seed.sql
docker exec -i tender-db psql -U postgres -d tender < task4_db/queries.sql
```

Запрос 1 — топ-3 компании по сумме выигранных тендеров за прошлый месяц.
«Выигранный» считается по подписанному договору, а не по флагу победителя в
ставке: между объявлением победителя и договором лот может уйти второму
участнику.

Запрос 2 — конкуренция и падение цены относительно НМЦ в разрезе заказчика:
сколько участников торговалось за лот и на сколько процентов победитель опустил
начальную цену.
